הנה קובץ טקסט מפורט שמחלק את הפרויקט לשלבים ברורים. כל שלב בנוי בצורה מדויקת ומאפשר בדיקות לפני מעבר לשלב הבא:

---

**Calendar Project Roadmap**

---

### **שלב 1: הקמת בסיס נתונים**

**מטרות**
- להקים בסיס נתונים מקומי (SQLite) לשמירת מידע על אירועים.
  
**שלבים**
1. יצירת קובץ בסיס נתונים בשם `calendar.db` בתיקיית `data/`.
2. יצירת טבלת אירועים בשם `events` עם העמודות הבאות:
   - `id` (מספר זיהוי ייחודי) - Integer, Primary Key, Auto Increment.
   - `title` (כותרת האירוע) - Text, כותרת קצרה שמתארת את האירוע.
   - `gregorian_date` (תאריך לועזי) - Text, בפורמט ISO (YYYY-MM-DD).
   - `hebrew_date` (תאריך עברי) - Text, בפורמט ידני (למשל, "י"ז באדר תשפ"ב").
   - `time` (שעה) - Text, בפורמט 24 שעות (HH:MM).
   - `description` (תיאור) - Text, תיאור מפורט של האירוע.
3. כתיבת פונקציות הוספה, מחיקה, ועדכון של אירועים בדטאבייס, ולוודא שכל פונקציה מחזירה הודעות שגיאה במקרה הצורך.

**בדיקות**
- בדיקת פונקציות הוספה ועדכון על ידי הוספת כמה אירועים ובדיקת התוכן בבסיס הנתונים.

---

### **שלב 2: יצירת שרת אפליקציות ב-Python**

**מטרות**
- לבנות שרת אינטרנט בסיסי ב-Flask, שיכול לשרת API לשליחה ושליפה של אירועים.

**שלבים**
1. התקנת Flask (`pip install flask`) והגדרת שרת בסיסי בקובץ `main.py`.
2. יצירת API לאירועים בתיקייה `api/` עם פעולות הבאות:
   - POST `/api/events` - הוספת אירוע חדש.
   - GET `/api/events` - שליפת כל האירועים.
   - GET `/api/events/<id>` - שליפת אירוע לפי מזהה.
   - PUT `/api/events/<id>` - עדכון אירוע קיים.
   - DELETE `/api/events/<id>` - מחיקת אירוע לפי מזהה.
3. שילוב פונקציות בסיס הנתונים של SQLite בפונקציות ה-API.

**בדיקות**
- בדיקה באמצעות Postman או כלי דומה כדי לוודא שכל פעולות ה-API פועלות כנדרש.

---

### **שלב 3: בניית ממשק משתמש (Frontend)**

**מטרות**
- ליצור ממשק HTML פשוט שיוצג למשתמש ויאפשר לו גישה ללוח השנה.

**שלבים**
1. יצירת תיקיית `templates/` עם קובץ HTML בסיסי (`index.html`) להצגת לוח שנה.
2. יצירת עיצוב CSS בתיקייה `static/css/` ולהוסיף את Bootstrap לעיצוב רספונסיבי.
3. יצירת JavaScript בתיקייה `static/js/` שיתחבר ל-API (שלב 2), ויבצע:
   - שליפת כל האירועים והצגתם בלוח השנה.
   - הוספת אירועים חדשים דרך טופס.
   - אפשרות מחיקה ועדכון של אירועים.

**בדיקות**
- וידוא שהממשק מוצג נכון במחשב ובמובייל.
- בדיקה שכל הפונקציות (הוספה, עדכון, מחיקה) פועלות דרך הממשק ומציגות הודעות שגיאה אם יש בעיות.
 
---

### **שלב 4: התקנה והגדרות גישה מרחוק**

**מטרות**
- להגדיר גישה לשרת מבחוץ באמצעות Port Forwarding או ngrok.

**שלבים**
1. במידה והגדרות ראוטר מאפשרות זאת, לבצע Port Forwarding לפורט בו רץ ה-Flask server.
2. במידה ולא, להתקין ולהשתמש ב-ngrok (`pip install ngrok`) כדי ליצור קישור חיצוני זמני לגישה לשרת.
3. וידוא שהשרת נגיש מבחוץ דרך הקישור ושהממשק נטען כראוי.

**בדיקות**
- גישה לשרת דרך רשת חיצונית (למשל, בעזרת מכשיר נייד שאינו מחובר ל-Wi-Fi) ובדיקת תקינות כל הפונקציות.

---

### **שלב 5: שילוב עם בוט טלגרם**

**מטרות**
- יצירת בוט טלגרם שיוכל לבצע פעולות בסיסיות כמו הוספה ושליפה של אירועים.

**שלבים**
1. התקנת הספרייה `python-telegram-bot`.
2. יצירת קובץ `bot.py` בתיקיית `bot/` עם הפונקציות הבאות:
   - `/add_event` - הוספת אירוע דרך הבוט.
   - `/show_events` - הצגת רשימת האירועים.
   - `/delete_event` - מחיקת אירוע לפי מזהה.
3. חיבור הבוט לשרת Flask כך שכל פקודה תשלח בקשה ל-API (שלב 2).

**בדיקות**
- בדיקת כל פקודה באופן ידני ובדיקת אינטראקציה תקינה עם בסיס הנתונים.

---

### **שלב 6: עיבוד שפה טבעית (NLP) ומודל שפה**

**מטרות**
- להוסיף תמיכה בשפה חופשית דרך מודל NLP כדי לבצע פעולות מורכבות דרך הבוט והממשק.

**שלבים**
1. חיבור מודל שפה (למשל `transformers` של Hugging Face).
2. עיבוד שאלות ותשובות כמו: "הצג לי את כל התורים לרופא בחצי שנה הקרובה".
3. עדכון הממשק כך שיכלול אפשרות לשליחת שאילתות בשפה חופשית.

**בדיקות**
- בדיקה שהשאילתות מבוצעות בצורה נכונה ושהמשתמש מקבל תשובות מתאימות.

---

סיום










המבנה של הפרויקט שלך מצביע על ארגון מסודר של קבצים ותיקיות, שמסייע בניהול קוד ובפיתוח אפליקציה. הנה הסבר על התפקיד של כל תיקיה עיקרית והקבצים החשובים שבהן:

### 1. תיקיית `app`
תיקיית הליבה של האפליקציה שלך, שבה נמצאים הקבצים והקוד העיקרי.

- **`api`**: 
  - מכילה את הקוד שמטפל בבקשות API. כאן תמצא את הקבצים שמבצעים את הלוגיקה של האפליקציה, כמו קבלת נתונים, עיבוד נתונים והחזרת תשובות ללקוח.

- **`static`**: 
  - מכילה קבצים סטטיים כמו CSS ו-JavaScript. 
  - **`css`**: קבצי עיצוב של האפליקציה, המגדירים את המראה והתחושה של הממשק.
  - **`js`**: קבצי JavaScript שמוסיפים אינטראקטיביות לאפליקציה, כמו עדכון דינמי של תוכן בדף.

- **`templates`**: 
  - מכילה את תבניות ה-HTML של האפליקציה. תבניות אלו משמשות ליצירת דפי אינטרנט דינמיים, שבהם ניתן להציג נתונים מהשרת.

### 2. תיקיית `bot`
תיקיה זו כנראה מכילה קוד עבור בוטים (כמו בוטים של Telegram או Discord). כאן תמצא את הלוגיקה והפונקציות שמבצעות אינטראקציה עם משתמשים דרך הבוט.

### 3. תיקיית `data`
תיקיה זו עשויה להכיל נתונים, קבצים או מסדי נתונים שמשמשים את האפליקציה. זה יכול לכלול קבצי JSON, CSV או כל פורמט אחר של נתונים.

### 4. תיקיית `instance`
תיקיה זו משמשת בדרך כלל לאחסון קבצים ספציפיים לסביבה, כמו קבצי הגדרות או קבצים רגישים (כמו מפתחות API). היא מאפשרת להפריד בין קוד המקור לבין הגדרות ספציפיות לסביבה.

### 5. תיקיית `migrations`
תיקיה זו מכילה קבצים שמבצעים מיגרציה של מסדי נתונים. 
- **`versions`**: כאן תמצא את הקבצים שמכילים את השינויים במסד הנתונים, כמו הוספת טבלאות או שדות חדשים.

### 6. תיקיית `venv`
תיקיה זו מכילה את סביבת העבודה הווירטואלית שלך, שבה מותקנים כל התלויות של הפרויקט. זה כולל את כל המודולים והספריות שהפרויקט שלך תלוי בהם.

### 7. תיקיית `__pycache__`
תיקיה זו נוצרת אוטומטית על ידי Python ומכילה קבצים מקומפלים של מודולים. היא משמשת לשיפור ביצועים על ידי שמירה של גרסאות מקומפלות של הקוד.

### סיכום
המבנה של הפרויקט שלך מסודר ומאורגן, מה שמקל על הפיתוח והתחזוקה של האפליקציה. כל תיקיה ממלאת תפקיד חשוב, והקבצים בתוכן מאפשרים לך לנהל את הקוד, את הנתונים ואת התצוגה של האפליקציה בצורה יעילה.
